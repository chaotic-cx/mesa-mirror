Mesa 26.3.1 Release Notes / 2026-11-18
======================================

Mesa 26.3.1 is a bug fix release which fixes bugs found since the 26.3.0 release.

Mesa 26.3.1 implements the OpenGL 4.6 API, but the version reported by
glGetString(GL_VERSION) or glGetIntegerv(GL_MAJOR_VERSION) /
glGetIntegerv(GL_MINOR_VERSION) depends on the particular driver being used.
Some drivers don't support all the features required in OpenGL 4.6. OpenGL
4.6 is **only** available if requested at context creation.
Compatibility contexts may report a lower version depending on each driver.

Mesa 26.3.1 implements the OpenCL 3.1 API, but the version reported by
the CL_DEVICE_VERSION, CL_DEVICE_NUMERIC_VERSION and CL_DEVICE_OPENCL_C_ALL_VERSIONS
clGetDeviceInfo queries depends on the particular driver being used.

Mesa 26.3.1 implements the Vulkan 1.4 API, but the version reported by
the apiVersion property of the VkPhysicalDeviceProperties struct
depends on the particular driver being used.

Bug fixes
---------

- Confidential issue #16794
- Fails to build on macOS < 10.12
- RadeonSI syncrhonization/barrier issue with Clear+Dispatch (Repro included)
- V3D: Labwc fails to allocate GBM buffers wider than 4096 pixels unless non-MSAA texture size limit is enabled
- VC4: Kodi on Pi 3: DRM PRIME / V4L2 fails after Mesa 26.2.6 with avfilter_graph_config: Function not implemented (-38)
- Windows ARM memory-leak
- Windows: u_memstream leaks MEM*.tmp files on SPIR-V shader compilation, stalling Lavapipe
- [ANV] Dragon's Dogma 2 Dark Arisen Glitch Shadows
- [OpenMW] Certain shaders cause visual corruption at the bottom of the screen when anti-aliasing is enabled, possibly Z-buffer related
- anv: compute shader writes to a storage image are partly lost after a render pass cleared the image earlier in the same command buffer on Intel LNL
- d3d12: NULL dereference in select_shader_variant() when compile_nir() fails
- d3d12: glClearTexImage through a texture view of another format flushes float32-denormal bit patterns to zero
- dozen: Driver should fail to enumate anything if requirements are not met
- dzn: Invalid minImageTransferGranularity specified on graphics/compute queue families
- dzn: Unaligned block-compressed textures are silently unsupported
- dzn: external memory buffers cannot be host mapped
- dzn: maxStorageBufferRange reports 128 MiB, but raw storage buffer views allow 512 MiB
- dzn: use different bit pattern in device addresses
- dzn: vkBindBufferMemory fails on memory imported from a host pointer
- nir_to_dxil has store_def and store_ssa_def and they're subtly different
- radeonsi: NULL pipe_memory_object dereference in si_resource_from_memobj()
- radv/aco: fast-linked GPL pipeline breaks fragment shader interlock on GFX11 (no s_waitcnt_vscnt before the jump to the PSepilog)
- radv: SIGSEGV in the hang-dump path with RADV_DEBUG=hang (null deref at 0x1a8) — no radv_dumps written
- radv: VK_EXT_descriptor_heap causes  performance slow down in FSR 4.1 workloads
- radv: attachment shading rate not broadcast to all views
- radv: fails to decompress when acquiring modifier-tiled images from the foreign queue
- rusticl/llvmpipe: heap corruption / SIGSEGV in \`llvmpipe_set_global_binding` when kernels on two queues are released by one \`clWaitForEvents`
- vkCmdDrawIndexed read access violation in Dozen (in dzn_descriptor_heap_copy)
- zink/ntv: pack_snorm_2x16 and unpack_snorm_2x16 unimplemented, aborts the process
